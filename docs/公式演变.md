# 公式演变

## 概述

BiliBoard 周榜排名公式自项目启动以来经历三次重大更迭，分为**远古公式**、**中间公式**和**现行公式**三个阶段。本文档详细记录各代公式的得分计算方法、时间修正系数 T 的算法、权重参数及对应期数。

---

## 技术浅析

### 排名公式的核心逻辑

榜单排名的核心是**得分计算**，由两大要素构成：

1. **时间修正系数 T**：反映歌曲投稿时间距统计周期的远近。新曲（本周内投稿）获得 T > 1 的加成，老曲（投稿早于周期起点）T ≈ 1.0 无加成。T 的设计经历了从离散阶梯表到连续对数函数的演进，后者更平滑、更公平。
2. **互动指标权重**：播放、收藏、点赞、投币四项指标各自乘以固定系数后求和。权重分配体现了官方对不同互动行为的价值判断——投币权重逐渐提升，反映其作为「最硬核」互动指标的认可度。

### 公式为何需要更新

- **公平性**：阶梯表 T 存在跳变（如 D0→D1 从 1.053 跳到 1.138），导致投稿时间仅差数小时、T 值却相差 0.08 以上。连续对数公式消除了这种跳变，T 值随投稿时间连续变化。
- **指标权重调整**：随着 B 站生态变化，官方对收藏和投币的价值判断也在调整。111 期收藏与投币权重互换即是一例。
- **开源 vs 闭源**：GitHub 上公开的公式仓库仅包含老公式（阶梯表 T，截至约 2026 年初）。新公式（连续对数）仅通过 Biliboard 专栏文章公布，需要通过数据库实际 score 反推验证才能确证。

### 我们的工作

我们通过以下步骤完成了公式的完整还原与验证：

1. **数据收集**：从官方 Biliboard 专栏（第 111 期）获取现行公式原文。
2. **反推验证**：以「numb numb」12 期周榜数据为样本，从官方得分反推每期的隐含 T 值，确认：
   - LOG 底数为**自然对数 ln**（非 Excel 默认 log10）
   - 103–110 期权重为 收藏×30 + 投币×15
   - 111 期起权重为 收藏×15 + 投币×30
3. **代码实现**：在 `rank.py` 中实现三代公式的 T 函数和权重常量，在 `boards.py` 中按 `issue_id` 自动选择对应公式版本。
4. **交叉核验**：自算得分（self_score）与官方 score 对照，确认偏差在合理范围内。

- **远古公式**（< issue 54）：保持不变，2× 播放系数 + 阶梯表 T（锚点 = 结算日）。

- **权重调整**：103–110 期收藏×30 + 投币×15，111 期起改为收藏×15 + 投币×30。

- 以「numb numb」12 期数据反推验证，确认现行公式 T 函数正确（LOG 底数为自然对数 ln）。
- 自算得分（self_score）与官方 score 交叉核验，偏差在合理范围内。

#### 修复的问题

- 排名显示错误：之前自算排名覆盖了官方排名，现改为保留官方排名为主字段，自算结果作为对照列。

- SQLite 数据库同步不完整：部分歌曲上榜期数数据缺失（如「numb numb」本地仅 8 期，官方共 12 期），需从官方 API 补充。

## 一、远古公式（< issue 54）

### 时间范围

2025 年中至 2026 年初（约第 1–53 期）。

### 得分公式

```
得分 = 2 × Δ播放 × t + 30 × Δ收藏 + 3 × Δ点赞 + 10 × Δ投币
```

### 时间修正系数 T

**锚点**：`period_end_ts`（本期结算日零点，即统计截止时间）

**发行天数**：

```
D = floor((period_end_ts − pubtime) / 86400)
```

D 为时间戳秒差向下取整 24h 天，**不可用日历天差**。

**阶梯系数表**：

| D | t |
|---|---|
| ≤1 | 2.47 |
| 2 | 2.06 |
| 3 | 1.69 |
| 4 | 1.39 |
| 5 | 1.18 |
| 6 | 1.08 |
| 7 | 1.03 |
| 8 | 1.01 |
| >8 | 1.0 |

无 pubtime 时按 D ≤ 1 处理（t = 2.47）。

### 权重参数

| 指标 | 系数 |
|---|---|
| 播放 (view) | 2.0 |
| 收藏 (favorite) | 30 |
| 点赞 (like) | 3 |
| 投币 (coin) | 10 |

### 常量定义（rank.py）

```python
OLD_WEIGHTS = {"view": 2.0, "favorite": 30, "like": 3, "coin": 10}
```

## 二、中间公式（≥ issue 54, < issue 103）

### 时间范围

2026 年初至 2026-05-19（约第 54–102 期）。

### 得分公式

```
得分 = Δ播放 × t + 30 × Δ收藏 + 3 × Δ点赞 + 10 × Δ投币
```

**关键变化**：播放的 2× 系数被移除，其余权重不变。

### 时间修正系数 T

**锚点**：`prev_period_end_ts`（前一期统计截止时间 = 本期结算日 − 7 天，即周期起点）

**整天数**：

```
d_days = (pubtime − prev_period_end_ts) / 86400
```

**阶梯系数表**（由官方 112 期 JSON 的 stats 周增量反推 implied_t 鲁棒估计得到）：

| 投稿日距周期起点整天数 | t |
|---|---|
| 0 | 1.0527 |
| 1 | 1.1381 |
| 2 | 1.3900 |
| 3 | 1.6061 |
| 4 | 1.6900 |
| 5 | 2.1574 |
| 6 | 2.4700 |

**求值逻辑**：

```python
k = max(0, min(6, int(round(d_days - 0.5))))
t = t_table[k]
```

投稿早于周期起点（老曲）时 t = 1.0，投稿距起点超过 7 天也视为 t = 1.0。

### 权重参数

| 指标 | 系数 |
|---|---|
| 播放 (view) | 1.0 |
| 收藏 (favorite) | 30 |
| 点赞 (like) | 3 |
| 投币 (coin) | 10 |

### 常量定义（rank.py）

```python
MID_WEIGHTS = {"view": 1.0, "favorite": 30, "like": 3, "coin": 10}
```

## 三、现行公式（≥ issue 103）

### 时间范围

2026-05-27（第 103 期）至今。

### 得分公式

```
得分 = Δ播放 × t + 收藏系数 × Δ收藏 + 3 × Δ点赞 + 投币系数 × Δ投币
```

其中收藏系数和投币系数在 111 期前后发生交换。

### 时间修正系数 T（连续对数公式）

**公式来源**：Biliboard 第 111 期专栏原文

```
t = LOG(EXP(DATE([投稿时间])-DATE([前一期周榜数据统计截止时间]))/86400 + 1) + 1
PS:时间均精确到秒
```

**数学表达**：

```
delta_days = (pubtime − prev_period_end_ts) / 86400
t = ln(exp(delta_days) + 1) + 1
```

**锚点**：`prev_period_end_ts`（前一期统计截止时间 = 本期结算日 − 7 天，秒级）

**数学性质**：

- 当 delta_days ≤ 0（老曲，投稿不晚于周期起点）→ t ≈ 1.0
- 当 delta_days > 0（新曲，本周内投稿）→ t > 1，delta 越大 t 越大
- 函数为连续光滑曲线，无阶梯跳变
- 经数据库实际 score 反推验证，LOG 此处为**自然对数 ln**（非 Excel 默认的 log10）

**兜底限制**：t ∈ [1.0, 50.0]

### 权重参数

#### 早期（103–110 期）

| 指标 | 系数 |
|---|---|
| 播放 (view) | 1.0 |
| 收藏 (favorite) | 30 |
| 点赞 (like) | 3 |
| 投币 (coin) | 15 |

```python
CONTINUOUS_EARLY_WEIGHTS = {"view": 1.0, "favorite": 30, "like": 3, "coin": 15}
```

#### 当前（111 期+）

| 指标 | 系数 |
|---|---|
| 播放 (view) | 1.0 |
| 收藏 (favorite) | 15 |
| 点赞 (like) | 3 |
| 投币 (coin) | 30 |

```python
DEFAULT_WEIGHTS = {"view": 1.0, "favorite": 15, "like": 3, "coin": 30}
```

**关键变化**：111 期起收藏与投币系数互换——收藏从 30 降为 15，投币从 15 升至 30，体现官方对投币指标权重的提升。

## 四、公式代对比总表

| 特性 | 远古公式 | 中间公式 | 现行公式 |
|---|---|---|---|
| 适用期数 | < 54 | 54 ≤ issue < 103 | ≥ 103 |
| 播放系数 | 2.0 | 1.0 | 1.0 |
| 收藏系数 | 30 | 30 | 30 (103–110) / 15 (111+) |
| 点赞系数 | 3 | 3 | 3 |
| 投币系数 | 10 | 10 | 15 (103–110) / 30 (111+) |
| T 函数 | 阶梯表（D = floor 天） | 阶梯表（d_days 登天） | 连续对数 ln(exp(d)+1)+1 |
| T 锚点 | 结算日零点 | 周期起点（结算日 − 7d） | 周期起点（结算日 − 7d） |
| 老曲 T | 按 D>8→1.0 | 1.0 | ≈1.0 |
| 最大 T | 2.47 | 2.47 | 连续增长（7 天约 8.0） |

## 六、代码实现

### 公式分代常量（rank.py）

| 常量 | 值 | 说明 |
|---|---|---|
| `NEW_FORMULA_FROM_ISSUE` | 54 | 54 期起切换为中间公式（T_TABLE 阶梯版） |
| `CONTINUOUS_FORMULA_FROM_ISSUE` | 103 | 103 期起切换为现行公式（连续对数） |

### 权重常量（rank.py）

| 常量 | 值 |
|---|---|
| `OLD_WEIGHTS` | `{"view": 2.0, "favorite": 30, "like": 3, "coin": 10}` |
| `MID_WEIGHTS` | `{"view": 1.0, "favorite": 30, "like": 3, "coin": 10}` |
| `CONTINUOUS_EARLY_WEIGHTS` | `{"view": 1.0, "favorite": 30, "like": 3, "coin": 15}` |
| `DEFAULT_WEIGHTS` | `{"view": 1.0, "favorite": 15, "like": 3, "coin": 30}` |

### T 函数实现

| 函数 | 适用期数 | 算法 |
|---|---|---|
| `time_correction_old` | < 54 | 阶梯表（D = floor 天，锚点 = 结算日） |
| `time_correction_mid` | 54–102 | 阶梯表（d_days 登天，锚点 = 周期起点） |
| `time_correction` | ≥ 103 | 连续对数 `ln(exp(d_days) + 1) + 1` |

### 公式选择逻辑（boards.py `_recalc`）

```
if formula_version == "old" or issue_id < 54:
    → 远古公式（OLD_WEIGHTS + time_correction_old）
elif issue_id < 103:
    → 中间公式（MID_WEIGHTS + time_correction_mid）
elif issue_id ≤ 110:
    → 现行早期（CONTINUOUS_EARLY_WEIGHTS + time_correction）
else:
    → 现行当前（DEFAULT_WEIGHTS + time_correction）
```
