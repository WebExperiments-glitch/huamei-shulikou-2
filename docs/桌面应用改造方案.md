# 桌面应用改造方案 — 「国民级」架构（Electron 壳 + 现有前端 + Python 内核）

> 状态：方案定稿，待实施
> 决策日期：2026-08-22
> 主仓库：https://github.com/WebExperiments-glitch/huamei-shulikou-2

## 一、目标与背景

**使命：让每个人都能直接使用，双击即用，无需开服务器、无需浏览器。**

- 用户痛点：当前是 Web（前端 React + 后端 Python），普通用户要 `npm run dev` + `uvicorn` 才能跑，门槛高。
- 原始意向：用 C/C++ 全量重写桌面应用。
- 调研结论调整：微信/QQ/钉钉/飞书等国民级应用的真实做法，并非「纯 C++ 原生 UI」，而是 **壳引擎（Electron/CEF）+ Web 前端 + C++/原生内核**。C++ 只用于内核（消息、加密、音视频、数据库），UI 渲染几乎全部走 Chromium/Web 技术（大厂自研的 Lynx 本质也是"为应用定制的 Web"）。
- **最终决策：采用与国民级应用一致的架构 —— Electron 壳 + 保留现有 React 前端 + Python 数据内核。**

## 二、为什么不是「C++ 全量重写」

1. **会丢失全部现有视觉资产**：液态玻璃、WebGPU 粒子、ECharts 图表、Three.js 音乐可视化、30+ 页面，这些全是 Web 技术栈，C++ 重写=从零再做一个，成本数月起步且大概率更丑。
2. **杀鸡用牛刀**：性能瓶颈在 SQLite 查询 + 网络 API + 渲染，非语言层。换 C++ 不会更快。
3. **国民级应用的 UI 用的就是 Web 技术**：微信 PC（Electron）、QQ 新版（Electron）、钉钉/飞书（Chromium/CEF）。追随它们 = 走已被验证的路。

## 三、字体「复古/马赛克」根因（已调研确认）

用户反馈旧程序字体像 2000 年代、马赛克。**根因与技术栈基本无关**：

| 原因 | 说明 | 对策 |
|---|---|---|
| ① 渲染引擎 | 旧代码走 GDI 位图渲染，小字号用内置点阵 → 锯齿；现代走 DWrite/Direct2D 矢量光栅化 → 平滑 | Electron/Chromium 天然使用现代渲染。C++ 用 Qt 也需现代后端 |
| ② 字体选择 | 宋体为印刷设计、屏幕差；**微软雅黑**专为 ClearType 亚像素渲染优化 | Electron 默认可用雅黑；C++ 需 `QFont("Microsoft YaHei")` |
| ③ DPI-Aware | 程序未声明 DPI-Aware，系统按 96dpi 画完再 DWM 拉伸 → 双线性插值发糊 | Electron 天然 DPI-Aware；C++ 需嵌 manifest |

结论：**Electron 天然解决字体与 DPI 问题**，这也是为何选它而不用走 C++ 古老坑。

## 四、目标架构

```
术力口/
├── frontend/        # React 前端（源码，多端共享 UI）
├── backend/         # Python FastAPI 内核（数据/算法/AI）
├── app/             # 多端应用工作区（Windows / 未来 APK）
│   └── desktop/     # Electron Windows 桌面版（main.js / preload.js / package.json）
│   └── android/     # 【未来】Android APK 工程
├── docs/            # 文档
└── data/            # 运行时数据（SQLite）
```

## 五、核心工程点

1. **后端随 exe 分发**：PyInstaller 将 FastAPI 打包为单 exe；Electron 主进程 spawn 启动、quit 时安全关闭。→ 达成「双击即用、完全离线」。
2. **API baseURL 改造**：前端现走 `vite proxy → localhost:8010`；Electron 内改为直连后端实际端口（动态分配或固定），删除对 vite proxy 的依赖。
3. **生命周期**：后端进程跟随主窗口；关窗后退出后端，避免孤儿进程（复刻后端已有的 shutdown_models 思路）。
4. **打包分发**：electron-builder 出 NSIS 安装包（图标、开机自启可选、托盘）。
5. **C++ 内核（长期）**：把后端中的热点（算法/加密/SQLite 封装）逐步用 C++ 插件加固，作为「国民级应用的 C++ 内核」——非推翻重写，而是渐进强化。
